# 환경 변수 검증 방식

- 상태: 채택
- 작성일: 2026-08-04

## 배경

환경 변수를 `import.meta.env`로 직접 사용하면 사용처마다 같은 문제가 반복된다.
환경 변수 이름에 오타가 나도 자동 완성이나 타입만으로는 충분히 막기 어렵고, 값이 비어 있거나 형식이 잘못되어도 실제 사용 시점까지 늦게 발견될 수 있다.
또한 환경 변수 접근 방식이 바뀌면 사용하는 모든 파일을 수정해야 한다.

## 결정. 환경 변수는 zod로 검증한다

- 선택한 방식: `import.meta.env`를 직접 사용하지 않고, zod 스키마를 통과한 `env` 객체를 사용한다.
- 이유: 환경 변수 이름 오타, 누락, 형식 오류를 앱 시작 시점에 확인할 수 있다.
- 직접 `import.meta.env`를 사용하는 방식의 문제:
    - 사용처마다 에러 처리를 직접 해야 한다.
    - 자동 완성이 약해 오타 가능성이 있다.
    - 환경 변수 호출 방식이 바뀌면 사용하는 모든 곳을 수정해야 한다.
- 방안 1: 직접 타입 스키마를 만든다.
    - 장점: 최소한의 타입 안정성을 얻는다.
    - 단점: 스키마 자체에 오타가 있거나 런타임 검증이 빠질 수 있다.
- 방안 2: zod로 강제한다.
    - 장점: 타입과 런타임 검증을 함께 얻는다.
    - 장점: 잘못된 환경 변수는 빠르게 실패하게 만들 수 있다.
- 감수할 점: 환경 변수를 추가할 때마다 스키마도 함께 수정해야 한다.

## 결과

- 환경 변수 접근은 `env` 객체로 모아 검증과 변경 지점을 한 곳에 둔다.
- 환경 변수를 사용하는 파일은 `import.meta.env` 대신 검증된 `env`를 import한다.
