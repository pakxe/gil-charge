# 주제

해당 컴포넌트(DrawPathStep)는 사용자가 지도 위에 원하는 위치를 선택할 수 있는 기능을 제공한다.

# 기능 목록

- 드로잉(사용자 인터렉션)
    - [ ] 웨이포인트 기능
- 현재 위치
    - [ ] 권한 허용
    - [ ] 중심을 현재 위치로 이동하기
- 데이터
    - [ ] 웨이포인트 기능으로 그려진 point[]
    - [ ] radius

# 리펙토링 평가/목표

아래 항목 중 1개 이상을 하면 리펙토링 성공이다.

- 책에서 학습했던 '인터페이스로 소통'을 적용해본다.
    - [ ] 도메인 로직을 수정했을 때 이 로직의 사용처를 수정해야하는가?
    - [ ] (중요하진 않을 것 같지만) react스럽게 캡슐화를 class가 아닌 dispatch 방식으로 해본다.
    - [ ] 구현의 변경이 외부에 영향을 주는가?

- 수정 영향도가 어떻게 개선되었는지 확인한다.
    - [ ] 도메인 로직과 UI 로직이 분리되었나?
    - [ ] 펜 기능을 추가한다고 가정하면 더 편리해졌나?
    - [ ] 다른 지도를 사용한다고 가정하면 더 편리해졌나?
    - [ ] 외부에서 내부 정보를 이용한 로직을 안쓰고 있는가?

# 개선 전 상황

- 상황: 하나의 파일에 모든 도메인 로직, 데이터, UI 로직, API 통신이 혼재되어있다
    - 문제: 수정 시 영향 범위가 넓고, 관련없어야 하는 곳도 영향 범위 내에 속하게 된다.
    - 문제: 특정 로직을 수정할 때 찾기 어렵고, 수정 부분을 파악하기 어렵다.
    - 문제: 솔직히 나는 너무 길어서 읽는 것만으로도 어렵다.

    - 함수 호출 방식으로 바뀌었으므로, acceptStatus가 loading으로 시작하는게 아니라 idle상태로 시작함. 데이터를 받아오는 중이라면 loading으로 변경
    - 아래부터는 ai피드백 이후
    - getCurrentLocation 메서드가 비동기이기 때문에 onFinally의 실행 위치가 잘못됨. 그렇지만, success, error 핸들 함수가 onFinally를 받는 것은 좀 책임에 벗어난다고 생각해서(애초에 try, catch, finally 문이 다 스코프가 분리되어있는 것처럼) request자체가 래핑해서 콜 하게 변경했음
